# Claude-vNext Integration Readiness

## Purpose

Prepare the next visible comparison between the current Claude-era board and the merged vNext forecast stack without changing Claude production logic, model parameters, value formulas, UI behaviour, or frozen legacy files.

This document is a diagnostic contract. It is not an acceptance decision and does not claim that vNext or a hybrid board is superior to Claude.

## Required inputs for a side-by-side board

### Claude original input

The Claude-side export must contain one row per player in the current board, or one row per player-lead if annual forecasts are already exposed.

Required identity fields:

- `stable_player_id` if already available; otherwise
- `legacy_key` plus `player_name` for temporary bridge diagnostics only.

Required value/rank fields:

- current displayed player value;
- current displayed rank;
- position/eligibility labels used in the board;
- any existing 1-year to 5-year components if exposed.

### Raw vNext input

The vNext export must contain the authoritative 804-player universe and five annual leads.

Required identity fields:

- `stable_player_id`;
- `legacy_key`;
- `player_name` as label only;
- `lead` in `{1,2,3,4,5}`.

Required forecast fields:

- meaningful-season probability;
- expected games;
- expected average;
- expected total points;
- threshold probabilities where available;
- point quantiles where available;
- provenance/artifact hash fields.

### Hybrid diagnostic output

The first hybrid output should be diagnostic-only and must contain all three views side by side:

- Claude original;
- raw vNext;
- hybrid candidate.

It must also include:

- stable-ID join status;
- source row counts;
- missing Claude rows;
- missing vNext rows;
- duplicate-ID checks;
- value delta;
- rank delta;
- largest positive and negative disagreements;
- subgroup labels for position, age band, age 30+, age 21 and under, zero-game players, and top-100 candidates.

## Join contract

1. Primary join: `stable_player_id`.
2. Bridge join: `legacy_key` only when moving between legacy scoring history and the authoritative registry.
3. Forbidden join: `player_name` alone.
4. Duplicate display names are expected to exist and must remain separate when IDs differ.
5. A comparison run fails if:
   - any `stable_player_id` is duplicated in either input;
   - any vNext player-lead key is duplicated;
   - any authoritative player is missing from the vNext five-lead export;
   - St Kilda Max King and younger Max/Maxwell King collapse into one row;
   - a zero-game player inherits established history through a name-only match.

## Forecast semantics to document before comparison

For every vNext field, the adapter must classify it as one of:

- unconditional forecast: already multiplied by event/opportunity probability;
- conditional forecast: applies only if a meaningful season occurs;
- probability/distribution field: bounded probability or quantile output;
- value-layer field: keeper-board conversion from forecasts to displayed value.

The adapter must not combine conditional and unconditional fields without an explicit conversion. The highest-risk error is double survival/fade: reducing a vNext expected value that is already unconditional by another Claude survival or age-fade factor.

## Required validations

A diagnostic adapter should fail loudly on:

- row-count drift from the authoritative registry;
- missing five-lead coverage;
- non-finite values;
- probabilities outside `[0, 1]`;
- non-monotone threshold probabilities;
- crossing point quantiles;
- duplicate IDs or player-lead keys;
- name-only joins;
- Max/Maxwell identity collapse;
- Claude rows without an explainable registry match;
- vNext rows without Claude coverage, unless explicitly marked as new/diagnostic-only.

## Blinded comparison slices

The morning comparison template should be populated without subjective conclusions until evidence exists. Required views:

- top 100 by Claude value;
- top 100 by raw vNext 5-year expected points/value proxy;
- every position group;
- age 30+;
- age 21 and under;
- zero-game players;
- largest positive vNext-minus-Claude deltas;
- largest negative vNext-minus-Claude deltas;
- players with implausible 1-to-5-year trajectories;
- duplicate-name and known-exception rows.

## Shortest critical path

1. Confirm the merged registry health report has zero critical identity issues.

6. Review largest disagreements and identity failures before considering any hybrid formula.
7. Only after review, define a single testable hybrid hypothesis in a new PR.
